# UI 设计系统与动效规范

> 配套 P3 完成。对应代码：`shared/src/commonMain/.../presentation/theme/`（令牌与主题）、
> `presentation/ui/`（组件与动效）。本文回答三个问题：颜色和字从哪来、什么时刻该有动画、
> 怎么在不开窗口的情况下核对界面。

## 1. 设计令牌（`theme/Palette.kt` + `theme/Theme.kt`）

整套界面只有一种"面"和一套语义色，全部集中在 `Palette` 对象：

| 令牌组 | 取值倾向 | 约束 |
|---|---|---|
| 底层 `Canvas / Panel / PanelMuted` | 暖纸色 `#F3F1EA` + 纯白 | 卡片永远是白纸，画布永远是纸灰，不许再发明第四种背景 |
| 文字 `Ink / Muted / Faint` | 墨色三级 | 正文 Ink、辅助 Muted、页码/时间戳 Faint，最多三级 |
| 主色 `Accent / AccentSoft / AccentLine` | 靛蓝 `#4A3ECB` | 一屏最多一个实心主按钮；AccentSoft 只用于选中/强调底色 |
| 语义 `Correct / Wrong / Pending` | 绿 `#0B7B58` / 赭红 `#BB441F` / 琥珀 `#94610E` | **判定结论的颜色全应用一致**，错题与错误反馈必须同色 |
| Hero `HeroStart / HeroEnd` | 深靛蓝渐变 | 只允许首页仪表盘使用，是全应用唯一的高饱和面 |

字体：正文默认 sans（中文优先，行高刻意抬到 1.55）；`displayMedium/Small` 用衬线体，
只用于正确率、连续天数这类"成绩单数字"。没有内置字体文件、没有 CDN——渲染全部走系统字体。

## 2. 动效规则（`ui/Motion.kt`）

三条硬规则写在 `Motion` 的文档注释里，新动画必须先对齐：

1. **时长**：交互反馈 120–260ms（`Quick/Standard`），状态切换 260–400ms（`Emphasis`）；
   超过 400ms 会被感知成卡顿。
2. **只动 transform / alpha / color**，不动布局尺寸（刻意展开的面板除外），避免重排抖动。
3. **没有任何循环动画**。页面静止时画面必须完全静止——这是学习工具，不是营销页。

已落地的交互动画：

| 场景 | 动画 | 组件 |
|---|---|---|
| 页面切换 | 按导航层级横向推入 + 淡入，返回方向相反 | `App.kt` 的 `AnimatedContent` |
| 页头 | 滚动后阴影渐显（"内容在下面"的提示） | `ScreenScaffold` |
| 换题 | 题干+选项整块推入，同题内作答不触发 | `PracticeScreen` 的 `AnimatedContent(item)` |
| 选项选择 | 背景/描边/字母徽标颜色过渡 + 按压缩放 | `OptionRow`（`toggleable` + `pressScale`） |
| 判题反馈 | 面板展开 + 结论徽标弹簧弹出 + ✓/✕ 放大进场 | `FeedbackPanel` / `MarkSymbol` |
| 进度条 | 从当前值平滑长到目标值（首帧从 0 生长） | `ProgressLine`（`rememberGrowth`） |
| 列表 | 逐项淡入上浮，间隔 45ms、封顶 6 项，只在首组出现 | `StaggeredAppear` |
| 数字 | 统计值滚动而非跳变 | `AnimatedCount` |
| 正确率环 | 圆弧从 0 扫到目标值 | `RingMeter`（Canvas） |
| 日历格子 | 悬停放大 1.35 + 底部明细切换 | `StudyCalendarPanel`（`hoverable`） |
| 提示条 | 进出场滑入滑出 | `BannerHost` |

按钮三件套 `PrimaryButton / SecondaryButton / GhostButton`：主按钮一屏最多一个；
选中态胶囊 `KtChip` 选中即实心主色（Material FilterChip 的 8% 底色在低亮度屏上看不出选中）。

## 4. 富文本与公式

题干、选项、解析都走 `presentation/richtext/RichText`。三条规则：

1. **纯文本走极速通道**：`Markdown.isPlain()` 判定没有任何标记时直接渲染 `Text`，
   排版、可选性、性能与旧版完全一致——真实题库里 99% 的题干都走这条路。
2. **有公式才自绘**：段落里出现 `$...$` 时改用 `InlineTypesetter`：
   汉字逐字可断、拉丁词整体不断、标点不打头（`，。）】`）也不打尾（`（【`），
   行盒按基线对齐，公式高时整行让高。断行是自己算的，因为 Compose 的 `Text` 无法把公式当作"字"参与换行。
3. **公式排版用 em 比例而不是字体表**：分式轴线 0.26em、分数线 0.05em、根号 0.52em、
   上下标 0.72x 且上标基线抬高 0.55×base.ascent。所有字形用 `TextMeasurer` 量、用 `drawText` 画，
   坐标是"基线坐标系"（y 向下为正），组合时只做平移。

排版器的颜色只有一种（正文色）：公式不单独着色，避免解析里的公式比正文更抢眼。

## 5. 个人笔记

笔记页（`NotesScreen`）是"列表 + 单一编辑器"的结构，不做第二套表单：

1. **三种归属，一套列表**：题库笔记 / 题目笔记 / 临时草稿共用列表，靠筛选胶囊区分。
   分成三个 Tab 会让人怀疑"我是不是找错地方了"，而笔记总量通常不大。
2. **只存引用，不复制正文**：`Note` 保存 `bankId` + `questionId`，不存题目副本。
   题库重新导入后笔记仍指向同一身份；关联失效时标红提示而不是删除笔记。
3. **入口跟着场景走**：练习页题干右上角「✎ 写笔记」直接带入当前题，
   题库卡片「笔记 N」带入该题库筛选。想法发生在读题那一刻，入口就该在那里。
4. **编辑器实时预览**：正文与题干共用 `RichText`，公式在本机渲染；
   标题可留空，列表用正文首段代替并剥掉 Markdown 标记，不让列表里冒出 `**` 或 `\dfrac`。

保存语义：编辑保留创建时间、只更新修改时间；置顶不改修改时间；删除要二次确认。
校验 fail-closed，但失败时停在编辑器并保留已写内容——笔记是用户自己的文字，不能因为一次校验失败就让人重写。

## 6. 工具箱

工具箱（`ToolboxScreen`）两个面板，同一页里用胶囊切换：

| 面板 | 结构 | 设计取舍 |
|---|---|---|
| 计算器 | 表达式输入 + 结果区 + 5×6 键盘 + 记录 | 键盘与实体科学计算器同序（函数在上、数字在右下、「=」独占右下角），手指不用重新学；表达式可键盘直接输入 |
| 单位换算 | 维度胶囊 → 数值 → 「从 / 到」单位 → 结果 → 常见对照 | 单位用**内联列表**而不是下拉菜单：展开后一眼看完整个维度，不会盖住结果 |

三条规则：

1. **实时结果不报警**：编辑中只显示算得出来的部分（`calcLive`），按「=」才给正式结论与错误。
   边打边红只会让人以为软件坏了；而按了「=」还装没事则是骗人。
2. **错误带位置**：`CalcError` 除了中文说明还带字符下标，界面显示"第 N 个字符附近"。
   一大串式子出错时，"语法错误"这四个字等于没说。
3. **入口跟着场景走**：练习页题干右上「∑ 工具」直接进入，返回时回到同一道题、输入不丢。
   从练习页打开即记下"本题用过辅助工具"，随作答写进历史（`AttemptRecord.usedTools`），反馈面板会标注。

配色沿用三件套：数字键白底、运算符与函数同色、`C`/退格用 `AccentSoft`、`=` 用实心主色。
结果数字用 `displaySmall` + 等宽字体，与首页的"成绩单数字"同一层级。

## 7. 知识图谱

个人图谱（`GraphScreen`）与关系编辑（`GraphEditorScreen`）两页。

**这一页的任务不是"画网络图"**，而是把断线说清楚：哪条关系指向的题库不在本机、
哪条关系的依据内容已经变了。所以列表按「有问题优先」排，同组内按最近修改倒序 ——
图谱不是按创建时间怀旧的相册。

| 界面元素 | 表达 |
|---|---|
| 四个数字 | 关系 / 涉及题目 / 缺失引用 / 依据暂停。第三个是"需要处理的题"，不是"总题数" |
| 关系徽章 | `↔ 相关`（靛）、`← 前置`（琥珀）、`⇒ 依据`（绿）、`⇄ 对比`（赭）。沿用已有语义色，不另造一套"图谱色" |
| 硬依赖徽章 | 琥珀「判题硬依赖」；目标缺失时右侧再加红色「依据暂停」 |
| 端点列 | 题库名（小字）+ 题干摘要（最多 3 行）。缺失时摘要变灰并加状态徽章 |
| 快照标签 | 只有对方缺席时才出现「快照」，文案明确写"只用来认出这是哪道题" |
| 复核确认 | 只在 `NEEDS_REVALIDATION` 时出现。它记录"人看过"，不是自动修复 |
| 编辑器 | 起点 / 关系 / 对判题的影响 / 目标 / 备注，五段纵向排列；两端各自有跨库搜索 |

**方向不能藏**。关系选择器下面永远有一句人话（"右边是左边的判题依据"），
硬依赖的开关在对称关系下直接禁用并说明原因 —— 让人点完保存才发现连反了，
比多占一行文字糟糕得多。

**编辑器里的摘要来自当前题库，不是快照**。编辑时看到旧摘录，会让人以为题库已经变了。

## 8. 扩展包

扩展包页（`ExtensionsScreen`）只有一个任务：**让人分清"装上了"和"生效了"。**
四个数字从左到右就是这条判断链：已装 / 生效中 / 等待题库 / 关系数。

| 界面元素 | 表达 |
|---|---|
| 四个数字 | 已装 N 个、生效中 N（题库在）、等待题库 N（先到一步）、关系 N 跨库。第二个和第三个互斥，加起来等于第一个 |
| 状态徽章 | `生效中`（绿）/ `等待题库`（琥珀）。没有第三种"部分生效"——包是整体绑定一个库 |
| 绑定行 | 「绑定题库 · 题库名」+ UUID 单独一行小字等宽。UUID 是唯一身份，必须显示，不能只给标题 |
| 关系/覆盖/注释三个小徽章 | 「4 条关系」「覆盖 2 题」「2 条注释」。覆盖题数按 `questionId` 去重，不按关系条数 |
| 注释展开 | 默认收起，展开后按题分组：带题号的挂题，没题号的排最后标「整库」。正文 Markdown + LaTeX 渲染，与笔记同一套 |
| 移除 | 红色 Ghost 按钮，底部一句话说明「移除一个包只会删掉它带来的关系与注释」 |

**包不改题库这件事必须写在页面上**，不能只写在文档里。页面顶部那句
「题目、答案、历史一条都不会被改」是这一页最重要的一行字 —— 用户对"补丁"的默认预期是它会改东西。

**版本号要显示成"从哪到哪"**：升级提示写 `1.0.0 → 1.1.0`，而不是只说"已更新"。
降级被拒时也说清"你现在是 1.1.0，这个包是 1.0.0，要装先移除"，
不提供"强制覆盖"按钮 —— 那不是高级选项，是数据丢失入口。

**本机没有文件选择器的平台**（JS/Wasm/iOS）在同一页说明"也可以直接把 .qbext 拖进窗口"，
不新开一页讲限制。

## 9. 多语言

多语言在这个界面里不是"语言切换器"那样一个控件，而是**三个地方各说一句实话**：

| 位置 | 表达 |
|---|---|
| 练习设置 · 语言 | 胶囊写 `简体中文 · zh-Hans 完整` / `英语 · en 2/6`。覆盖度必须和语言名放在一起 —— 只写"英语"会让人以为整库都能用英文练 |
| 设置页提示行 | 不完整时用琥珀色写"没翻译的 4 题不会被抽到 —— 不会拿另一种语言的题面顶替"；完整时用灰色写"切换语言等于换一套作答历史与错题记录" |
| 缺译文开关 | 只在真的有缺译文、且题库多于一种语言时出现。默认关闭：把另一种语言当译文塞过来，比少练几题糟得多 |
| 练习页副标题 | 多语言题库必写本场语言（`英语 · en`）；单语言题库不写，那是噪音 |
| 题干徽章 | 退回原文的题挂琥珀色「原文」—— 不挂就等于谎称这是译文 |
| 历史 · 语言筛选 | 只在历史里真的出现过两种以上语言时才出现；记录行里也标语言，题面按那次作答的语言显示 |

**为什么把覆盖度放在胶囊上，而不是单独一行统计**：用户选择语言的那一刻，最需要知道的
就是"选它我会少多少题"。放到别处，等于让人选完再失望。

**为什么「原文」徽章不用红色**：它不是错误，是降级 —— 琥珀色表示"注意，但可用"。
红色留给判错与数据损坏。

## 10. AI 讲解

AI 是一个**可选面板**，不是常驻功能。界面上要回答的只有三件事：现在能不能用、这次要花什么、这段内容可信到什么程度。

| 位置 | 表达 |
|---|---|
| 首页入口 | `✦ AI 讲解`，后面跟已有记录条数；没有记录时只写文字，不写"0" |
| 练习页题目右侧 | `AI 讲解` → 生成后变 `讲解`（靛蓝）；生成中 `生成中`（琥珀）；已采纳转绿。**平台不支持时整个入口不渲染** |
| 未配置时点入口 | 直接进 AI 页，而不是先弹一句"还没有配置"再让用户自己找 |
| 未作答 | 只给一条横幅"先作答再看讲解 —— 没作答就看，等于提前看答案"；按钮不弹面板 |
| 讲解面板 | 标题右侧挂状态徽章；正文用与笔记同一套 Markdown+LaTeX 渲染；底部一行写"由 {模型} 生成 · {状态} · N tokens" |
| 免责声明 | 面板底部固定一句"结构校验只保证文本能正常展示，不保证讲得对 —— 请对照教材判断"。这句不能省：把模型输出当教材原文是最常见的误用 |
| 失败 | 面板里红色写原因（HTTP 状态 + 脱敏后的服务端说明 + "不会自动重试"），并保留上一次的内容，标注来源 |
| 审核 | `有用` / `没用` / `重新生成` 三个按钮，只有人工点击才会改变审核状态 |
| AI 页 · 状态卡 | 徽章四态：`本平台不支持`（灰）/ `未配置`（琥珀）/ `未同意上传`（琥珀）/ `可用`（绿）。下面两个数字：今日调用、今日 token；再一行金额与剩余次数 |
| AI 页 · 成本闸门 | 三个数字框（单次输出、每日次数、每日 token）+ 一个金额框。金额旁明确写"单价留 0 表示不计费用" |
| AI 页 · 上传同意 | 独立一块浅底面板，未勾选时用琥珀色写"现在不会发送任何题目内容" |
| AI 页 · 记录 | 每条一行：状态徽章 + 模型 + 相对时间 + 题号 + 语言 + 字数 + 花费；点击展开 600 字预览 |

**为什么"未同意"用琥珀而不是灰**：灰是"还没做"，琥珀是"做这件事之前需要你点头"。前者是状态，后者是待办。

**为什么生成失败也占一次额度**：失败同样发了一次请求。不计数的话，"点五十次重试"就成了绕过上限的办法。

**为什么不在面板里放"帮我记到笔记"**：跨模块写操作会让"这条笔记是谁写的"变得含糊。要做的话，应该由用户在笔记里引用讲解，而不是讲解偷偷写笔记。

## 11. 批量生成

批量是"成本量级差两个数量级"的操作，界面上必须让人一眼看出**这次要发几次请求**。
所以排队列与开始是两个按钮，中间隔着一次扫描。

| 位置 | 表达 |
|---|---|
| AI 页入口 | 一块浅底面板：`批量生成` + 待续任务数徽章 + `▤ 批量生成队列 · N 个任务` |
| 排新队列 | 题库胶囊 →（多语言时）语言胶囊 → `本次最多问几道`（默认 50，0 = 不限）→ `排进队列` |
| 排队列后 | 任务面板出现，状态 `待开始`，进度 `0 / N 0%`，四个数字全为 0 或 N，**本次已发出 0 次请求** |
| 开始前 | 面板顶部一行说明："只处理这个库里还没有讲解的题。已经有的会被排除，不重复请求。" |
| 运行中 | 状态 `生成中`（靛蓝）；按钮变 `暂停` + `取消`；旁边一行"当前这道题返回后才会停（打断请求也会扣费）" |
| 暂停 | 状态 `已暂停`（琥珀），说明写原因（用户点的 / 本次上限到 / 某日预算到）；按钮变 `继续` |
| 完成 | 状态 `已完成`（绿），说明"共 N 道：成功 N，跳过 N；本次发出 N 次请求"；`待处理 0` 转灰 |
| 取消 | 状态 `已取消`（红字弱按钮触发），已生成的数字保留不动 |
| 失败 | `失败 N` 转红；下方可展开失败项，每行 `题号前 12 位 + 原因`，超过 8 条写"还有 N 条没有列出来" |
| 成本 | 一行 `本次已发出 N 次请求，还剩 M 次额度；估算 ¥x · N tokens`；任务结束后不再显示"还剩" |
| 任务记录 | 只在有 2 个以上任务时出现；每行左状态徽章、中 `题库 · 语言` 与 `N/M 已生成 · K 失败`、右相对时间 |
| 平台不支持 | 整页只有一句话："联网 AI 目前只在桌面端接入。这里不会排任何队列，也不会偷偷发请求。" |

**为什么"排进队列"与"开始"要分开**：合成一个"一键生成全部"，用户就永远没机会在扣费前看到总数。
这一块最贵的错误不是"跑错了"，是"不知道自己要跑多少就跑了"。

**为什么"预算不足"显示成暂停而不是失败**：失败会让人去查网络、查题库；暂停配一句"今日次数已用完"
才说得清发生了什么，也说明"明天点继续就行"。

**为什么取消不清空未处理的项**：取消往往是"我现在不想跑了"，不是"这个任务作废"。
清空之后要重排一遍，等于把用户已经做过的范围选择也一起丢掉。

**为什么"待处理 0"要转灰**：靛蓝在这个界面里一直代表"还要做"。任务跑完还亮着靛蓝，
看起来像还剩活没干。

## 12. 题库更新（`.qbpatch`）

这一页只做一件事：**在改任何东西之前，把会变的东西摆出来。**
补丁自己没有"应用"以外的路可走 —— 所以页面必须把话说在按钮前面。

| 位置 | 表达 |
|---|---|
| 入口 | 拖入 / 选中 `.qbpatch` 直接进这一页；从导入页进来时不停在"导入成功"，而是立刻摊开改动清单 |
| 页头 | 补丁名 + `v2.0.0` 靛蓝胶囊；右侧灰胶囊 `第 1 版 → 第 2 版` |
| 第二行 | `目标题库《…》 · 本地 3 题`；作者备注原文照登（不截断、不改写） |
| 第三行（最淡） | `补丁 starter-v2 · 基于内容 fe59fc06… · 这份补丁只改上面这个题库第 1 版的内容` |
| 四个数字 | `新增` / `修改` / `删除` / `答案变更`；为 0 的一格转灰，不为 0 才上色 |
| 答案变更块 | **排在统计数字之后、改动清单之前**，琥珀底：`答案变更 1 道` + "你在其中练过 2 次 —— 那些记录不会因为这次更新而改变" + 每条 `旧 … / 新 …` + 底部一行"历史不会被改写：作者改答案不等于你当时答错了" |
| 没有答案变更 | 灰底一句话："这次更新没有改动任何一道题的正确答案 —— 你的练习历史与现在的判题口径仍然一致" |
| 改动清单 | 每行一个符号方块 + 类型 + 题号 + 题干（最多两行）+ 变更行：`＋`绿 新增 / `~`靛 题面变更 / `!`琥珀 答案变更 / `－`红 删除 |
| 底部 | 灰底一句"应用之后：题库变为第 2 版，题库卡片上会显示版本号；改动过的题会重新生成 AI 讲解；练习历史一条都不动" + `应用更新` + `取消` |
| 不需要更新 | 灰底 `不需要更新` + 原因。**没有按钮** —— 这里不该有"再试一次" |
| 比本地旧 | 琥珀底 `这个补丁比本地题库旧`：写明本地是第几版、补丁只到第几版、应用等于往回退，因此不提供应用按钮 |
| 对不上 | 红底逐条列冲突码（`BANK_MISMATCH` / `CONTENT_DIVERGED` / `EXPECT_MISMATCH`…），并写明"什么都没有改。补丁不提供「尽力应用」模式" |
| 找不到题库 | 琥珀底："补丁只做增量修改，没法单独安装 —— 先用完整包把那个题库装上" + 目标题库 ID 前 8 位 |
| 校验不通过 | 红底前 8 条（码 + 中文原因），超过写"还有 N 条没有列出来" |
| 应用后 | 回首页，绿横幅：`题库《…》已更新到第 2 版：新增 1、修改 2、删除 0。其中 1 道题的答案变了，你有 2 条历史记录是按旧答案判的 —— 那些记录一条都没改` |
| 首页题库卡 | `第 2 版` 灰胶囊，**只在 `contentRevision > 1` 时出现**，位置在题数胶囊左边 |

**为什么"答案变更"要单独成块，而不是混在改动清单里**：清单回答"改了什么"，这一块回答
"我过去的判断还算不算数"。后者是用户真正需要停下来想一秒的事，混在列表里会被当成一条普通改动划过去。

**为什么 `不需要更新` 用灰不用红**：补丁没生效不等于出错。红色会让人去查文件、查版本；
其实该做的是关掉这一页。同样，`PATCH_NO_EFFECT` 在逻辑里是个"好消息"。

**为什么没有"尽力应用"按钮**：改一半的结果比不改更糟 —— 事后无法分辨哪里被改过，
也没法把历史对上号。拒绝时要给理由，但不能给一条"我知道有风险，照做"的路。

**为什么首页只在第 2 版以后才显示版本号**：绝大多数库一辈子停在第 1 版，给它们挂个"第 1 版"是噪声。
而一旦装过补丁，这个数字就成了"我收到的是哪一版、这个补丁要不要再装一次"的唯一依据。

## 13. 历史复核

这一页的唯一职责：**不替用户决定"那次作答算不算数"，但把决定的材料准备齐。**

页面本身的结构就是这条立场：没有主按钮、没有默认选项、没有"推荐"。

| 位置 | 表达 |
|---|---|
| 入口 | 首页工具栏 `↻ 复核 2`，**只在有待复核记录时出现**。没有待办就不给入口 —— 一个永远显示"0"的按钮只是噪声 |
| 页头 | `历史复核` / `答案改了之后，旧记录怎么算由你决定`；返回键回首页（清单不丢，回来不用重扫） |
| 顶部说明 | 琥珀底：`判定对不上 2 条` + 一段"这些记录当时判的结果跟按现在的题目内容重算的结果不一样" + 一段灰字说明两个按钮分别会改什么 |
| 批量 | `全部按新答案`（次按钮）+ `全部维持当时判定`（弱按钮）。**批量也刻意不做成主按钮** |
| 单条卡片 | 第一行：题型胶囊 + 题库标题 + `2 天前` + 右侧题号；第二行：现在的题干（最多三行）；然后两行对照 |
| 对照两行 | `当时判的 · 正确`（绿软底）+ 当时的作答按当时顺序翻成 `A. 客观物质性、B. …`；下一行 `按现在重算 · 错误`（红软底）+ `现在的标准答案：…；E. 直接现实性` |
| 单条按钮 | `按新答案：错误`（次按钮）+ `维持：正确`（弱按钮）。两个都是"具体后果"，不写抽象的"接受/忽略" |
| 没有候选 | 绿勾图标 + `没有需要复核的记录` + "说明你练过的题没有被改过答案，或者改过之后你已经表态过了" |
| 有不可复核的 | 灰底一行：`还有 N 条记录对应的题目已经不在题库里了 … 但历史里一条都没少` |
| 底部 | 灰底一句"复核不会改写历史记录本身 … 就算哪天想反悔，把决定再改一次就行 —— 原始那一行永远还在" |
| 首页卡片 | 最近提交里，改判过的标 `复核改判`（琥珀）、维持的标 `复核保留`（灰），都排在判定胶囊**左边** |
| 历史页 | 判定下面多一行：`复核改判：当时判 正确，你按新答案改成了 错误`（琥珀）/ `复核：你确认维持当时的判定（正确）`（灰） |
| 批量后 | 绿横幅：`已按新答案复核 2 条记录：统计与错题本已跟着变，历史记录本身没有改写` |

**为什么整页没有一个主按钮**：主按钮的意思是"这是你该做的事"。这里不存在该做的事 ——
按新答案会动统计与错题本，维持会让以后再做这道题时口径不一致，哪个更对取决于用户怎么看那次作答。
给一边加重，就是在替他做决定。

**为什么按钮上写结果而不是写动作**：`按新答案：错误` / `维持：正确` 比 `接受` / `忽略` 好，
因为用户要判断的正是"我愿不愿意让这条变成错误"。抽象动词会让人先翻译一遍再判断。

**为什么"维持当时判定"也要写一条记录**：不写的话，这条记录下次还会出现在列表里 ——
"我看过了，不改"是一次真实决定，必须能被记住。这也是没有"忽略"选项的原因：
忽略等于下次再问一遍。

**为什么改判过的记录要标出来**：历史里出现一条与当时不一致的判定，如果看不出为什么，
读起来就是"记录被偷偷改了"。标记的作用不是装饰，是让"这是后来改的、改之前是什么"永远查得到。

**为什么首页徽章不解析题目**：算它只需要"历史里哪些题落在答案变更清单里" —— 读已经载入的历史
与修订日志就够了。为了一个数字去解析十万道题，会让首页变慢，而真正的差异等用户点进去再算。

## 14. 来源真实性

这一块要解决的不是"题目对不对"，而是**"这道题是他写的还是抄的"**。
软件无法回答这个问题（它没有那本书），能做的只有两件事：把作者的声明原样摆出来，
以及把"作者没说"和"作者说是原创"在视觉上彻底分开。

| 位置 | 表达 |
|---|---|
| 练习页 · 位置 | 题干之下、选项之上。**作答之前**就该知道这道题哪来的，等判完才看到等于事后通知 |
| 作者原创 | 灰字 `作者原创`；若还参考了某本书，写 `作者原创（参考 甲教材 · 2020）` |
| 改编 / 引用 | 灰字 `改编自 甲教材 · 2020 · 第二章第三节` / `引自 …`。版次与定位是重点，不是书名 |
| AI 参与生成 | 琥珀胶囊 `AI 参与生成` + `参考 甲教材 · 2020`。**不是警告，是让人知道这段文字可能没经过人审** |
| 来源未标注 | 最淡的灰 `来源未标注`。既不是"可信"也不是"不可信" |
| 标了出处没标性质 | `出处 甲教材 · 2020 · …（性质未声明）` —— 已有的信息照实说，括号里说明缺的是什么 |
| 首页题库卡 · 第三行 | `作者 · 出处 3 处 · CC-BY-4.0`，`Palette.Faint`、单行省略。三项全空则**整行不渲染** |
| 补丁预览 | 出处改动归 `◎ 出处变更`（`Palette.Muted`），不混进 `~ 题面变更` |
| 整包摘要不对 | 红底 `CONTENT_DIGEST_MISMATCH`，写明"这份包和作者发出来的那一份不是同一份内容" |

**为什么"未标注"必须写成字，不能留空**：留空在中文界面里默认读作"没有特别说明，大概是原创"。
一个作者从没说过的话，被界面替他补上，是这一块最严重的错误 —— 而且事后无法从数据里看出来
当初到底是"没说"还是"说了原创"。所以 `来源未标注` 是唯一的、必须存在的第五种状态。

**为什么"未标注"不用琥珀、也不用红**：琥珀在这个界面里表示"注意，但它有问题"（原文降级、AI 参与、待复核）。
"作者没说"不构成问题指控 —— 大量正常题库本来就不标出处。用琥珀会变成对作者的软性指责。

**为什么出处的版次与章节要显示，而不是只显示书名**：同一本书 2010 版和 2023 版可能把这道题删了。
只说"出自甲教材"，等于给读者一个查不回去的引用。

**为什么首页三项全空就不渲染**：写一行"未知作者 · 出处 0 处 · 无许可"看着像质检报告，
而绝大多数用户只想知道"这是我昨天装的那个库吗"。**不写"未知作者"这个词** —— 它与"来源未标注"同理，
是替作者贴标签。

**为什么摘要不显示成"已验证"的对勾**：`contentDigest` 只是内容指纹，没有密钥。
对勾会让人以为"这份包经过签名认证"，而它能证明的只有"这份包与作者打出来的那份逐字节一致"（防手滑），
不能证明"作者就是这个人"（防冒充）。所以界面写"内容摘要一致"，不写"已验证"、不写"安全"。

## 15. 备份与迁移（`.qbk`）

这一页是"数据不在云上"的代价与补偿：没有账号、没有同步，换设备只能靠一个文件。
所以它只回答三个问题：**导出的是什么、恢复会覆盖什么、覆盖之后还能不能退回去。**

| 位置 | 表达 |
|---|---|
| 入口 | 首页工具栏 `⇩ 备份`，**只在数据真的落在磁盘上的平台出现**。Web / iOS 关掉就没了，那里给按钮等于承诺做不到的事 |
| 页头 | `备份与迁移` / `整份数据打成一个文件带走；或者用一份备份把本机整体换掉` |
| 上次恢复被打断（有才显示） | 页面**最上面**一张卡片，标题按情况变：`上次恢复被打断：本机数据没被动过` / `已经退回原来的数据` / `备份里的数据已经接上` / `上次恢复其实已经完成了` / `数据和旧备份都不见了` / `发现一份读不懂的恢复日志`。正文一句话说清发生了什么，然后两行路径：`现在生效的数据：… · N 个文件`、`被换下来的旧数据：…（需要退回去就把它改回原位）`，右下角 `知道了` |
| 上次恢复被打断 · 颜色 | 需要用户动手的三种（数据不见了 / 日志读不懂 / 收拾现场出错）用错误底色 + 红标题；已经处理好的三种（回滚 / 前滚 / 只差收尾）用中性底色 + 墨色标题 —— **"已经修好了"不该染成红色**，否则红色会变成装饰 |
| 上次恢复被打断 · 首页横幅 | 启动时在首页说一次，点「知道了」之后连刷新也不再提。备份页那张卡才是能回头再看的那一份 |
| 导出 · 说明 | "把题库、作答历史、复核决定、笔记、图谱、扩展包与 AI 记录一起打包成一个 .qbk 文件" |
| 导出 · 本机概况 | `本机：1 个题库 · 3 道题 · 1 条历史 · 0 条笔记`；下一行（更淡）是数据目录的绝对路径 |
| 导出 · 按钮 | `导出备份`（主按钮）。旁边一句状态：`打包后会让选保存位置` / `先导入一个题库，再来备份` / `当前平台不能保存文件` |
| 导出之后 | 绿底一张凭据：文件名、`3 个文件 · 文件大小 4 KB · 2026-10-21 15:53`、`内容摘要 301b1c0d…`、一句"两台机器导出同一份数据，摘要会一样" |
| 未加密提示（开关关闭时） | 琥珀底一块：`备份没有加密` + "能打开这个文件的人就能看到你的全部题目、笔记与作答记录。别放到公共网盘、群聊或别人的电脑上"；打开加密开关后这块**换成**灰底（见下两行） |
| 加密开关 | 胶囊 `加密：关` / `加密：开`（**默认关**），旁边一句"任何人拿到这个文件都能看到全部内容" / "只有输对口令的人能打开这份文件" |
| 加密 · 口令 | 两个密码框：`口令（至少 10 个字符）`、`再输一次`；下面一行实时提示：`还差 N 个字符` / `两次输入不一样` / "四个不相关的词（例如「自行车-海豚-毛线-九月」）比一个复杂但短的词更牢" |
| 加密 · 后果确认 | 必须用户自己点的胶囊：`请确认：忘记口令就打不开` → 点过变成 `我知道：忘记口令就打不开`。没点之前导出按钮是灰的 |
| 加密 · 说明块 | 打开开关后，琥珀块**换成**灰底：`加密之后只有口令能打开` + `口令 → PBKDF2-HMAC-SHA256（600000 轮）→ AES-256-GCM` + 红字"忘记口令就打不开：没有找回、没有后门、没有提示问题" + 灰字"明文里只剩几个统计数字" |
| 加密之后 | 绿底凭据多一个 `已加密` 小标；文件数从统计里取；末句改成"摘要仍然对得上，但加密备份每次的盐和 nonce 不同，文件字节不会一样" |
| 引用自检 · 位置 | 夹在**导出与恢复之间**：导出面板说的是"要打包的东西"，自检紧接着说"这些东西之间的引用我核对过了"，恢复放在最后。次序本身就是一句话：先看清、再换掉 |
| 引用自检 · 标题 | `引用自检`，右侧淡字 `核对于 2026-10-23 17:01` —— 交代这是**什么时候**的判断，不让人以为它一直实时 |
| 引用自检 · 结论 | 一块面板，底色随结论变：全部接上用 `CorrectSoft` 绿、有缺口用 `PendingSoft` 琥珀。第一行是结论本身：`核对了 3 处引用，其中 2 个目标接不上；引用的 1 张图里缺 1 张` |
| 引用自检 · 看了什么 | 第二行（Muted）逐项列出 `看了：1 个题库 · 3 道题 · 2 条图谱关系 · 1 条笔记`。**零项不写**：`0 个扩展包 · 历史覆盖 0 个题库` 只是噪声，可缺了哪一项又让人以为那一项没核对 |
| 引用自检 · 缺口明细 | 小标题 `接不上的目标（2 个，指向同一个目标的已合并成一条）`，每行三段：目标（`《KT-QBF 综合示例》里的 q-deleted-004` / `题库 bank-thermal-handbook`）、`题目已不在题库里 · 图谱关系、笔记 共 2 处`、一句该怎么办。最多 5 行，超出写 `还有 N 个没列出来 —— 上面的数字是全部` |
| 引用自检 · 缺图 | 小标题 `题目里写了、但这份数据里没有的图（1 张）`，每张两行：assetId（等宽字体）` · 《题库名》`、`被 N 道题引用，图片文件不在数据里` |
| 引用自检 · 操作 | 次按钮 `重新核对` + 幽灵按钮 `收起`；底下一句灰字："接不上不等于坏：题库被卸载、题库更新时删了题，都会让一条引用暂时指空 —— 装上 bankId 相同的题库，它会自己接上" |
| 引用自检 · 空态 | 还没跑或被「收起」之后：灰底 `核对这份数据里的引用有没有指空` + 说明 + `核对一次`；正在跑时换成 `正在核对引用…` 与一句"把图谱关系、笔记、扩展包绑定、历史记录各自指向的题库与题目对一遍" |
| 恢复 · 加密未解锁 | **中性底色**卡片（不是红色）+ "口令不对、文件被改过、写到一半断掉 —— 三种情况都会解不开，而且在密码学上分不出是哪一种" + 口令框 + `解锁` 次按钮 |
| 恢复 · 解不开 | 红字一条：`解不开：口令不对，或者这份文件被改动过 —— 这两件事在密码学上分不开`；口令框还在，可以重试 |
| 恢复 · 已解锁 | 绿字 `已解锁 · AES-256-GCM 校验通过：这份文件没有被截断，也没有被改过任何一个字节`，随后才是次按钮 |
| 恢复 · 说明 | "选一份 .qbk，先看清里面有什么，再决定要不要换掉本机的数据"；灰字补一句"恢复之前一个字节都不会写；恢复失败会回滚" |
| 恢复 · 按钮 | `选择备份文件`（**次按钮**）。有备份待确认时旁边出现 `取消` |
| 恢复预览 | 文件名 → `2026-10-21 15:53 于 Windows 11 · 桌面端 导出 · 应用 0.9.0` → `备份格式 v1 · 数据布局 v1 · 3 个文件 · 原始数据 2 KB` → `里面有：1 个题库 · 3 道题 · 1 条历史 · 0 条笔记` → 下一行（Muted）`本机现在：1 个题库 · 1 条历史` |
| 确认恢复 | 次按钮 `用这份备份替换本机数据` + 灰字"本机现有数据会被移到旁边的目录，不删除" |
| 备份不可用 | 红底卡片：文件名 + 逐条错误码与原因（最多 6 条，超出报数）。**没有确认按钮** |
| 平台不支持 | 一块灰底："这个平台没有可备份的数据" + 原因 + "备份做的是把磁盘上的文件原样打包，桌面端的数据写在用户目录下，所以只有那里有备份入口" |
| 页脚 | 灰字一句："备份是给你自己的：它不做内容校验，也不判断题目对不对 —— 只保证把文件原样搬回去" |

**为什么导出是主按钮、恢复只是次按钮**：导出是安全动作（多一份拷贝），恢复是覆盖动作。
两个做成同样重量，等于训练用户把"确认覆盖"当成顺手一点 —— 那正是数据丢失最常见的入口。

**为什么"上次恢复被打断"要放在最上面，而且不自动消失**：那一屏上所有别的问题
（要不要加密、备份多大、本机有多少数据）都以"现在生效的是哪一份数据"为前提。
前提没说清，下面的数字全是错的。不自动消失的理由更简单：
这是"你的数据刚才差点出事"的记录，用户看没看过只有他自己知道；
替他判断"这条不重要"就是在替他判断他的数据重不重要。点过「知道了」才消失，是因为那时他确实读过了。

**为什么修好了也用同一张卡、只是换个颜色**：换成一句"一切正常"会把这次事故抹掉 ——
用户下次不会知道自己的数据曾经处在两个目录之间。卡片留下的是**发生过什么**，
颜色只表达**现在要不要动手**。这两件事分开，界面才不会用"没事了"掩盖"出过事"。

**为什么预览里要并排列出"备份里有"和"本机现在有"**：只报备份里有什么，用户还得自己回忆本机有多少；
只报本机会被覆盖，又不知道换来什么。两个数字挨在一起，"我要不要换"才是个能回答的问题。

**为什么"文件大小"和"原始数据"分开写**：它们是两个数（4 KB vs 2 KB），
同一个词"大小"配两个值会让人以为其中一个算错了。

**为什么旧数据要留在旁边而不是删掉**：这是这一页唯一真正的退路。用户误恢复之后，
第一反应是"我的东西呢" —— 界面上直接给出那个目录的路径，比任何"操作不可撤销"的警告都管用。
代价（占磁盘）也照实说，下次恢复才清理。

**为什么"要口令"不写成错误**：加密备份读进来只拿到信封，界面据此换成口令输入框 —— 那是**下一步**，
不是失败。把它混进红条"这份备份不能用"里，用户会以为文件坏了；而真正解不开时又要说清
"口令错和文件坏分不出来"，两件事挤同一句话就都说不清了。

**为什么默认不加密**：默认加密会让"备份完了却打不开"成为最常见的失败 —— 口令忘在三天前。
所以默认关，两侧的说明都固定在原位：关着时说的是"谁拿到文件谁能看"，打开时换成"忘记就打不开"。
界面上不存在"加密了但没人告诉你"的状态。

**为什么必须输两次 + 必须自己勾一句**：忘记口令的后果不可逆，而打错一个字母在密码框里看不出来。
这两步不是防用户，是把"不可逆"这件事在动手之前说一遍。勾选不接受预勾，因为默认勾选等于没问。

**为什么把 KDF 和密码写在页面上**：这句话让用户知道自己依赖的是什么，也方便将来换成 Argon2id 时
有据可查（参数就在文件里）。写"军工级加密"之类的形容词不提供任何信息。

**为什么自检的底色是琥珀而不是红**：接不上是**既有状态**，不是损坏 —— 卸载一个题库、
用补丁删掉一道题，都会让引用暂时指空，而用户什么都没做错。红色留给"需要你动手、而且你可能已经丢了东西"；
这里用红，等于告诉用户他的数据坏了，实际上装回那个题库就全好了。反过来，缺图也是琥珀：
图不在会让一道题的题干空一块，但它不是"数据被毁"。

**为什么按目标合并、不按记录一条行**：十条关系指着同一个没装的题库，用户要处理的是**一个题库**。
按记录列出来，"1 个问题"会被显示成"10 个问题"，于是用户第一反应是"这功能坏了"而不是"我该装回那个库"。
整库缺失合并成一条、题目级缺失逐题保留，也是同一个理由：前者是同一个目标，后者是两个不同的人删了两道题。

**为什么历史只查库级**：补丁删题是正常操作。历史指向一道已被删掉的题，是"当时确实做过"的证据，
不是悬空。把这种也报出来，自检就会永远不干净 —— 一个永远有告警的面板，等于没有告警。

**为什么结论要同时出现在横幅和面板里**：横幅是**点完导出那一刻**的回执（"打包成功了，顺便核对了"），
面板是可以回头看的那一份。两处说的是同一句话（共用同一个 `summary`），不是两种说法 ——
同一个事实在界面上有两种措辞，用户就得自己判断哪句更可信。

**为什么自检不拦导出**：指空的引用不该成为拿不到备份的理由。挡住导出换来的是"数据绝对干净"，
代价是用户失去唯一的退路 —— 而这个退路存在的意义，正是为了应对"数据已经不干净"的情况。

## 16. 移除题库

题库卡片最底下一行是「移除题库」——`Palette.Faint` 的 Ghost 按钮，不在主路径上，但必须能找得到：
导错一个包却没法从书架上拿下来，比"多一个按钮"更糟。

| 界面元素 | 表达 |
|---|---|
| 首次点击 | 原位换成一句 `题目文件会删除，历史与笔记保留`（`Palette.Wrong`）+ `确认移除`（红）+ `取消` |
| 二次确认 | 不弹模态框：确认态就在按钮原位，换卡片或离开首页自动退回，不存在"点开对话框忘了关" |
| 移除成功 | 绿横幅：`已移除题库《…》（12 题），1 条指向它的关系随之删除，没做完的那场练习已放弃。历史与笔记一条没动。` |
| 本来就没有 | 不弹横幅。磁盘上已经没有这个库时，界面只把它从内存里放掉 —— 对一次没发生的删除说"已移除"是编 |

**为什么叫"移除"不叫"删除"**：删除听起来像把内容抹掉，而它做的只是"从书架上拿下来"。
历史、复核、笔记、收藏一条都不动 —— 错题本里那些题会标为「关联已失效」，
笔记里那几句是自己写的字，一个字都不该少。用户对"删题库"的默认预期是"我的错题本要没了"，
这句话必须由横幅当场澄清，而不是等他自己去翻。

**为什么关系要跟着删**：关系描述的是"两段内容之间的联系"。一端的内容已经不在了，
这条联系就没有意义 —— 留着它，图谱页会永远挂着几条"缺失"，而用户明明刚说过不要那个库。
这不是级联删除内容：删掉的是描述联系的记录，内容早在题库那一步没了。

**为什么不能删单题**：题库内容属于作者，应用只提供"整库移除"与"追加自己的题"。
要改单题，正道是作者发 `.qbpatch`，由你在补丁预览里逐条核对后再应用 ——
"就地改一道别人的题"会让内容版本、指纹与历史全部失去参照。

## 17. 键盘作答

练习页是唯一需要"一天按几百次"的界面，所以只有它有键位。规则写在
`presentation/practice/PracticeKeyboard.kt`（纯函数），界面只负责接线。

| 按键 | 行为 |
|---|---|
| `A`–`Z` / `1`–`9` | 选中对应位置的选项，与点一下同一个效果（`A` = 第一个 = `1`） |
| `Enter` | 未提交时提交；已判完时继续下一题（最后一题去总结） |
| `Ctrl/Cmd + Enter` | 简答题提交 |
| 带 `Ctrl`/`Alt`/`Cmd` | 不拦 —— 剪贴板、输入法、浏览器刷新照常 |

**为什么简答题的裸回车不提交**：逐字符判定的题型，答案本来就可能是多行。回车被拿去提交，
这种题就再也写不完整。宁可多按一个 `Ctrl`，也不让人怀疑回车键坏了。

**为什么带修饰键的一律不拦**：`Ctrl+C` 应该是复制。一个"顺手吃掉按键"的练习页，
会让人以为整个应用有问题 —— 而这类问题极难归因。

**为什么重组题没有键位**：它的作答是「按次序点片段」，屏幕上没有可数的 A/B/C。
硬给它编一套（比如数字键按次序追加）会让"按键"在两处含义不同，学一次不够、还得学第二次。

**为什么提示只在桌面与 Web 出现**：手机上没有物理键盘，写「按 A 选择」只会让人找按键。
提示本身也是设计的一部分 —— 键位没人知道，等于没有。

**同一份规则不写两遍**：提交按钮的可用状态与回车键的语义读同一个
`PracticeController.canSubmitCurrent`。这条不是洁癖：早先界面自己另算一份，只认选项，
于是重组题的「提交作答」永远是灰的 —— 判题写好了，用户却点不到。

## 18. 已知限制（如实）

| 限制 | 说明 |
|---|---|
| 只有浅色主题 | 深色需要另一套语义色，未验证不假装支持；所有颜色已令牌化，加深色只改 `Palette` |
| 无图标字体 | 用字形（← ★ ✓ ✕）与 Canvas 自绘替代，不依赖任何外部资源；题目附图走 `MediaStore` 真实解码，不是占位图 |
| 含公式的段落不可选中 | 自绘 Canvas 没有文本选择；纯文本段落仍是普通 `Text`，可正常选中复制 |
| 数学排版是子集 | 无 `align` 环境、无自定义宏、无字距微调；超大括号封顶 3.4 倍缩放 |
| 笔记不能导出 | 只有本机 `notes-v1.json`；换设备要重新写（题库可以重新导入，笔记不行） |
| `StaggeredAppear` 只播一次 | 滚动/筛选不重播入场动画，避免每次操作整页闪烁 |
| 键盘快捷键未接 | 桌面端 Enter 提交、Esc 暂停、计算器回车求值等尚未实现 |
| 计算器记录不落盘 | 只存在内存，关掉应用就清空；它的定位是"算一个数"，不是笔记本 |
| 计算器不做符号运算 | 只有数值求值：不解方程、不化简、不保留分数与根号的精确形式（`1/3` 显示为 0.3333333333） |
| 图谱没有可视化网络 | 只做列表：几千条关系的力导向图既难读又费性能。关系表达的是"依据/前置"，不是拓扑美感 |
| 图谱端点摘要是纯文本 | 列表行不渲染公式（会变成多行 Canvas，破坏行高），公式显示为「公式」；完整内容在编辑器与题目页 |
| 缺失引用不能改指向 | 题库没了只能重新导入、删关系或保留标注；"把关系改指到另一道题"要重新建一条 |
| 扩展包关系不可就地编辑 | 图谱里点编辑会跳回扩展包页并说明原因：包是作者的单向声明，本机改动会在下次装包时被覆盖 |
| 扩展包页无进度条 | 导入是同步完成的（几千条关系读一遍），不显示进度；包大到需要进度条时，说明它该做成题库 |
| 历史不记扩展包 | 作答记录不区分"当时有没有这条依据"，也不记依据来自哪个包。移除包后无法回溯"那次是看着谁答的" |
| 语言选择不记忆 | 每次进设置页都按"界面语言能对上就用它"重新决定；不会记住上次给这个库选过英文 |
| 覆盖度胶囊可能挤 | 语言多、名字长时 `FlowRow` 会换行；没有做成下拉，因为下拉会把"每种语言翻了多少"藏起来 |
| 无法在应用内补译文 | 只能重制包再导入；界面编辑器只写源语言 |
| AI 只在桌面端有入口 | 其他平台的传输层为 null，练习页干脆不渲染入口；AI 页写明"本平台不支持"，不放一个点了没反应的按钮 |
| 讲解面板没有流式输出 | 等完整返回才显示；长回答期间只有一行"正在请求…"，没有逐字动画 |
| 讲解不能选中复制 | 与题干同理：含公式的段落是自绘 Canvas；纯文本段落仍是 `Text` |
| AI 页表单不能"取消" | 改动只在点保存时生效，但离开页面再回来会回到已保存的值；没有单独的"放弃修改"按钮 |
| 批量队列没有并行 | 一次只发一个请求；没有"2/4 路并行"选项，速度完全取决于服务端 |
| 批量不能按范围筛 | 只能选整个题库 + 语言；选题型、标签、错题范围都还不支持 |
| 失败项不能就地重试 | 要重来只能再排一个队列，界面上没有"重试这几道"的按钮 |
| 单任务最多 500 道 | 超出时截断并在一行说明里报数，没有分页或自动接力 |
| 补丁只能一版一版打 | 从第 1 版跳到第 3 版要连装两个补丁；没有"累积补丁"，页面上也不会替你排队 |
| 补丁没有制包界面 | 只有命令行 `qbpatch.py`；界面里能看、能应用，不能做 |
| 修订日志只能看，不能回滚 | 只记摘要（改了几道、哪几道答案变了），不存旧题目正文；退回上一版要重新导入完整包 |
| 删除的题在历史里"关联已失效" | 不做级联删除：作答记录还在，但题目已经不在了，错题本按"关联已失效"标注 |
| 复核页没有主按钮也没有推荐 | 两个选项等重是刻意的，代价是第一次进来的人可能不知道该点哪个；页头那句"由你决定"就是全部指引 |
| 复核清单没有筛选与分页 | 候选一次全列；没有"只看这个题库""只看本周"，也没有"处理完这一屏"的批量 |
| 复核页不显示已处理的记录 | 处理完就从列表消失，没有"我刚改了什么"的回看列表；要回看只能去历史页看标记 |
| 复核不能改判成第三种结果 | 只能"按新答案"或"维持"，不能标成部分正确、不能手填判定 |
| 不可复核的记录只报数 | 题目被删掉的那批记录只能看到"N 条"，点不进去；要看详情得去历史页（那里标着"关联已失效"） |
| 首页徽章可能偏保守 | 它按修订日志算（"这道题答案改过"），不重算题目；所以装了补丁但本地内容其实没变的极端情况下，数字可能比复核页里的候选多一点 |
| 移除题库没有撤销 | 题目文件当场删掉，没有回收站；唯一退路是备份（`.qbk` 里含整个库）。横幅刻意不写"可恢复"，因为除了备份确实没有第二条路 |
| 移除题库时会丢一场没做完的练习 | 会话里只有题目引用，题库没了就答不下去；已提交的记录仍在历史里，但"做到第几题、写了什么草稿"会一起消失 |
| 出处只显示一行 | `url` / `note` 已读入并存储，界面没有可展开的详情页，链接也点不开；想知道"这本书是谁写的、去哪找"只能去看制包文件 |
| 出处不能在编辑器里改 | 手工新建的题永远是「来源未标注」；要标出处只能重新导入或走 `.qbpatch` |
| 摘要不给"安全"结论 | 只比内容是否一致，无签名无身份；界面刻意不写"已验证""可信"，因为那两句都超出了它能证明的范围 |
| 备份只能在桌面端做 | Web / iOS 的数据在内存里，没有可备份的东西；Android 还没有"保存到用户选的位置"的通道。两处都只写原因，不摆按钮 |
| 加密备份**默认关闭** | 打开要输两次口令并确认后果。默认加密会让"备份完了却打不开"变成最常见的事故 |
| 加密备份上限 64 MiB | 纯 Kotlin 的 GHASH 约 20 MB/s；更大的数据只能用不加密的备份（上限 500 MB），页面会明说 |
| 口令不可找回 | 没有提示问题、没有密钥文件、没有后门。忘记口令 = 那份备份永久打不开 |
| 明文信封仍会泄漏统计 | 别人能看到"几个题库、几条历史、来自哪台机器、何时导出"；文件名与摘要都在密文里 |
| 不加密时仍然全裸 | 关掉加密开关，同一个文件谁拿到谁能看 —— 琥珀块就是为这句话存在的 |
| 恢复不能合并 | 只有"整体替换"。合并出一种既不是备份、也不是本机的第三种状态，比不合并更糟 |
| 恢复后旧数据仍占磁盘 | 它被改名叫 `*.pre-restore-<时间>` 留在旁边（这是退路），下次恢复才清。磁盘紧张要手动删 |
| 中断只能修好，不能零丢失 | 恢复全程记日志，断电/被杀之后下次启动会回滚或前滚；但断电正好落在 rename 与写日志之间时，靠的是现场本身可分辨 |
| 自愈只在启动时跑一次 | 运行中数据目录被外部删掉，应用不会当场发现，下次启动才处理 |
| 没有"撤销上一次恢复"按钮 | 退路是把 `*.pre-restore-*` 手工改回原名，界面只给路径 |
| 引用自检只看"在不在" | 只核对"谁指着谁、目标还在不在"，不看指得对不对：关系建错了对象、把 A 题的前置写成 B 题，它看不出来 |
| 自检不检查内容对错 | 题干写错、答案标错、笔记有错别字，都不是它的事；页脚那句"不做内容校验"就是为它留的 |
| 缺图只核对文件名 | 文件在就认为在，不比对字节：被换成另一张图、或被截断都发现不了（逐文件摘要属于备份容器的职责） |
| 自检的面板只列前 5 个 | 目标与缺图各最多 5 行，剩下的写"还有 N 个 —— 上面的数字是全部"；要看完整明细得去图谱页或笔记页 |
| 自检不提供一键清理 | 题目级的指空引用是用户自己建过的东西，自动抹掉比留着更糟；要删只能去图谱页逐个删 |
| Web / iOS 的图片一项会跳过 | 那两处的数据在内存里，给不出文件清单，面板明说"图片没有核对"而不是假装查过 |
